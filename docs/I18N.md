# i18n 架构

首批语言：**简体中文（zh-CN，源语言/默认）+ 英文（en）**。架构支持继续加语言。
覆盖 web 面板、`@danlu/core` 共享层、服务端 ntfy 推送、桌面客户端 UI 与 Rust 通知。
CLI 输出本期保持中文（运维场景，见"边界与例外"）。

## 运行时（packages/core/src/i18n.ts）

自研轻量运行时，零新增前端依赖：

- `Locale = 'zh-CN' | 'en'`，模块级状态 + `useLocale()`（useSyncExternalStore）。
- `resolveLocale(stored, sysLang)`：显式选择优先；`auto` 时系统语言以 `zh` 开头 → zh-CN，其余 → en；取不到系统语言按 zh-CN（产品默认）。
- `registerMessages(locale, catalog)`：应用启动时注册自己的目录；core 域目录随模块加载注册。
- `createT(zhCatalog)`：返回**键位带类型**的 `t`，键集 = 应用键 ∪ core 键，拼错键 tsc 报错。
  各应用在 `src/lib/i18n.ts` 导出绑定的 `t`，组件一律用它。
- 插值 `{name}`；复数条目 `{one?, other}` 按 `Intl.PluralRules` 选择，计数参数 `count` 和 `n` 等价。
- 回退链：当前语言 → zh-CN → 键名本身。
- **切换语言时根组件以 `key={locale}` 重挂整棵树**（web main.tsx、desktop main.tsx/tray.tsx），
  所有组件（含 memo）拿到新文案，调用点保持纯函数 `t('key')`。查询缓存在模块级 QueryClient，不受重挂影响。
  副作用：切换时未保存的表单草稿重置（切换器在设置页，低频操作，可接受）。

## 目录与键约定

| 目录 | 内容 |
|---|---|
| `packages/core/src/locales/{zh-CN,en}.ts` | 两端共用：`common.*` 按钮、`status.*`、`time.*`、`gpu.*`、`fail.*`、`queue.*`、`error.*` |
| `web/src/locales/{zh-CN,en}.ts` | 面板：`login/layout/home/jobs/job/newjob/resources/terminal/compare/settings/notfound.*` |
| `desktop/src/locales/{zh-CN,en}.ts` | 客户端：按页面/组件命名空间 |

- 键名扁平点号、按页面/组件命名空间；**禁止在调用点运行时拼键**（静态映射表可以，如 format.ts 的 statusKeys）。
- zh 是源目录（`satisfies Catalog`）；en 类型为 `{[K in keyof typeof zh]: Message}`，
  **缺键、多键都会在 typecheck 报错**，不需要额外的对齐测试。
- 文案里的数字、单位（GB/MB）、`GPU 0,1` 这类数据保持原样；只翻译词语。
- 术语统一：UI 计数与标签用 GPU/GPUs（解释性散文里 card 可保留）；结束提醒统一 completion alert；
  保留策略清理统一 prune；连不上统一 unreachable。Rust/ntfy 无复数机制，含 {n} 的句子用中性措辞
  （"running jobs: {n}"）避开单复数；TS 目录用 {one, other} 复数对象。
- `fmtTime` 保持 `YYYY-MM-DD HH:mm:ss` 定长格式（信息密度与等宽对齐），不随语言变化。
- 语言名用 endonym（"简体中文"/"English"），两种语言下都不翻译。
- 品牌"丹炉 Danlu"不翻译；炼丹风味只在空状态和标题，英文做克制转创。

## 语言选择与持久化（三处独立）

| 面 | 存储 | 默认 | 切换入口 |
|---|---|---|---|
| web | localStorage `danlu-lang`（显示偏好，同主题约定） | auto（navigator.language） | 设置→偏好→外观→语言 |
| desktop | `state.json` Prefs.lang（Rust 通知也要用） | auto（sys-locale 解析 OS 语言） | 设置→常规→语言 |
| ntfy 推送 | settings 表 `ui.notify_lang`（prefChoice，复用 POST /api/settings/prefs） | zh-CN | 设置→手机推送→推送语言 |

- web：`index.html` 内联脚本首屏前设 `<html lang>`；根组件 effect 设 `document.title`。
- desktop：`set_prefs` 广播 `prefs-changed` 事件，主窗和托盘经 `useLangSync()`（lib/lang.ts）同步切换。
- 推送语言是服务端行为，与面板显示语言解耦；不触碰 config.toml（"服务从不修改通知配置"不变量）。

## 翻译边界

**翻译**：UI chrome（含 aria-label、placeholder、title、空状态、document.title）、共享格式化、
API 错误（经错误码）、推送/通知文案、有机器码的持久化文本（显示时合成）。

**不翻译（数据/诊断，保持中文，原样显示）**：

- 任务日志与终端内容（程序输出）；runner 日志横幅（`logs.BannerPrefix` 不变量不动）。
- 审计 `detail`（持久化中文；action 标签在前端按码翻译）。
- doctor 的 `Detail`/`Fix`（诊断输出；检查标题按 check ID 翻译）。
- 快照 note / skip reason。
- CLI 全部输出（未来路径：同款 messages 模式 + LANG 环境变量）。
- 无 `fail_kind` 的旧任务 `fail_reason`（回退原文）。

## 后端错误码（增量，APIVersion 不变）

多客户端可能同时用不同语言，所以 Go API 错误经机器码翻译：

- 错误 JSON：`{"error": "中文原文", "code"?: "snake_case", "params"?: {...}}`。
- 机制在 `internal/api/errors.go`：`writeErrC`（直发码）+ `writeErrE`（从
  `scheduler.ValidationError` / `settings.InputError` 自带的码优先，其次 17 条哨兵错误映射，都没有回退纯文本）。
  校验错误经 `scheduler.invalid(code, params, format, ...)` 与 `settings.InvalidC(code, msg, params)` 带码。
- core `ApiError` 带 `code/params`；两端统一经 `apiErrorText(err)` 显示：
  命中 `error.<code>` 目录键 → 本地化；否则回退服务器原文（旧服务器、未编码错误天然兼容）。
  **显示错误不要直接取 `.message`**（拼进 `t()` 参数也不行），审计脚本会拦。
- 范围/偏好/安全校验错误**按项编码**（`range_<name>[_zero]`、`pref_invalid_<name>`、`security_*`），
  整句进目录：zh 与服务器 `error` 原文逐字一致，en 是完整句子。机器键名、原始单位（s/day）不适合
  直接展示，所以不用通用插值；服务器改 specs/prefSpecs 的范围或标签时同步改 core 目录。
- 码表（108 个）：core 目录 `error.*` 键与之一一对应；新增错误码时同步加 zh/en 键。
  一个码只对应一句中文原文；意思不同就另起一个码。500 内部错误不编码（诊断原文直显）。
- 同步由 Go 单测守住：`internal/api/catalog_test.go` 用 go/ast 扫 `internal/`、`cmd/` 里所有字面量码
  （`writeErrC`、scheduler `invalid`、`settings.InvalidC`）和 `sentinelCodes`，核对目录有键、
  字面量原文与 zh 逐字一致（模板用调用点的字面量参数填好再比）、zh/en 的占位符都在 params 里，
  并反查目录里没有服务器已不发的码（客户端自己的 `network/gate_expired/token_revoked` 在 `clientOnlyCodes`）；
  `internal/settings/catalog_test.go` 逐项触发范围/偏好校验，核对 `range_*`、`pref_invalid_*` 的 zh 原文。
  两者经 `internal/i18ntest` 读 TS 目录（只给单测用）。

## 持久化文本的显示时合成

- 失败原因：`fail_kind + fail_detail + exit_code + ext_seen` 合成（core `failReasonText`/`failText`，
  Rust `fleet.rs::fail_reason_text` 同一套逻辑）；旧记录无分类时回退原文。
  `fail_detail` 是迁移 17 新增列（host_oom 三态 worker/confirmed/guess137、信号名），
  由 `logs.ClassifyFailure` 产出，随结束事件下发。start 类的 `fail_detail` 是不带前缀的原始启动错误
  （写任务清单失败时前面加 `danlu.json: `），显示为 `fail.start_detail`（"启动失败: {detail}"）；
  推送只说"任务启动失败"，不存这段自由文本。
- 队列暂停：`kind + job_id + fail_seconds`（fail_fast）或 `disk_available_gb/disk_min_gb`（disk）
  合成（core `queuePauseText`）；`reason` 作旧服务器回退。
- 保留策略预览：`reason_code`（resume/age/size）翻译，回退原文。
- "只有退出码"判断：core `exitCodeOnly` 优先 fail_kind，旧服务器回退原文正则（审计 ALLOWLIST 放行）。

## 服务端与 Rust 文案

- ntfy：`internal/notify/messages.go` zh/en 文案表（键集/占位符对齐单测），`Service.Lang` 读
  `ui.notify_lang`，**发送时合成**（completion 存 fail_kind/fail_detail/exit_code，旧持久化批次回退 Reason）。
  句间拼接用 `concatSentences`（中文不留空格，英文留一个）。
- 桌面 Rust：`desktop/src-tauri/src/messages.rs` zh/en 表（95 键，对齐单测）；模块级语言状态经
  `set_lang` 更新（启动时与 set_prefs 时取 `LocalState::resolved_lang()`）。通知、提醒、命令错误、
  托盘菜单都在构造处按当前语言合成；切换语言时 `tray::refresh_language` 重建托盘菜单。
  `[通知]` stderr 开发日志、expect/panic 诊断保持中文。

## 加一门语言

1. core/web/desktop 各加 `locales/<locale>.ts`，键集镜像 zh-CN（类型强制）。
2. `Locale` 联合类型、`resolveLocale`、三处语言选择器加选项。
3. Go `internal/notify/messages.go` 与 Rust `messages.rs` 加文案表。
4. 跑全套检查 + 审计脚本（scripts/i18n-audit.mjs）。

## 抽取工作流

- 新文案一律进目录，禁止硬编码用户可见字符串（注释仍用中文）。
- `node scripts/i18n-audit.mjs` 扫描 web/src、desktop/src、packages/core/src，**CI 门禁**，有问题退出码 1：
  - 用户可见 CJK（状态机剥注释；品牌"丹炉"与 ALLOWLIST 例外放行）；
  - 错误对象的 `.message`（`e.message`、`q.error.message`、`(err as Error).message`）：要经 `apiErrorText`，
    例外进 MESSAGE_ALLOWLIST；
  - 复数条目（en 目录里值是 `{one, other}` 的键）的调用点必须传 `n` 或 `count`，否则英文永远是复数形式。
  新增例外必须写进对应 ALLOWLIST 并注明原因。
- 英文更长：保留现有截断/折行模式，手机 360px 抽查，不得降低信息密度（PRODUCT.md 红线）。
- 全角标点（：、　）也是文案：分隔符走 common.colon / common.list_sep 等键。

## 已知边界（英文界面下仍显示中文的数据）

- 旧记录无 fail_kind 的 fail_reason、旧服务器的 queue.reason / retention reason。
- 审计 detail、doctor Detail/Fix、快照 note/skip reason（持久化/诊断文本）。
- 任务日志、终端内容、runner 横幅（程序输出与日志数据）。
- CLI 输出（本期不做；未来路径：同款 messages 模式 + LANG）。
- start 类失败的自由文本详情（译前缀后附原文）。
