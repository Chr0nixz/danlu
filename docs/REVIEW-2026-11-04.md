## P1 · 定版前修复

### 1. 清理会删除快照重跑的相对路径产物

**WSL 已复现。** 用 `mkdir -p checkpoints` 和 `printf model > checkpoints/best.pt` 创建产物，再从快照重跑。重跑成功后，checkpoint 位于 `run/<id>/code/checkpoints/best.pt`。执行 `danlu prune --older-than 0s` 后，checkpoint 被删除，官方输出目录中的 `danlu.json` 仍存在。自动清理与 CLI 共用删除逻辑。

建议把重跑生成的产物纳入保护，并为现有运行目录处理兼容。回归用例应同时验证日志和快照能按规则清理、相对路径产物仍可读取。 [重跑目录](../internal/scheduler/scheduler.go#L673) · [清理路径](../internal/retention/retention.go#L73) · [保留策略说明](../README.md#L192)

### 2. 密码变更后，旧网页终端仍可执行命令

**WSL 已复现。** 登录并连接终端后，用 CLI 修改密码。旧会话请求 `/api/me` 返回 `401`，已建立的 WebSocket 仍能发送 shell 命令并在服务器创建文件。终端只在握手时鉴权，后续输入直接写入 PTY。

建议将连接与握手所用的凭证关联，让会话注销、到期和设备令牌吊销都能使对应连接失效。回归用例应在保持连接的情况下验证撤权后无法继续执行命令。 [密码变更](../cmd/danlu/main.go#L675) · [WebSocket 握手](../internal/api/terminal.go#L153) · [终端输入](../internal/api/terminal.go#L202)

### 3. 第二个 `serve` 会让原服务崩溃

**WSL 已复现。** 让第一个实例的任务阻塞在 `.bashrc` 加载阶段，再用同一个 `DANLU_HOME` 启动第二个实例。第二个实例先把仍在准备的任务退回队列，随后才因端口已占用而退出。等原实例再次占位后释放 `.bashrc`，两个启动流程争用同一个 `starting` 条目，原服务发生空指针崩溃。

建议在恢复任务前取得数据目录的单实例锁，并确认监听成功后再开始调度。回归用例应验证第二实例退出时，数据库、原服务和在途任务保持一致。 [启动恢复](../cmd/danlu/main.go#L329) · [端口监听](../cmd/danlu/main.go#L389) · [启动状态](../internal/scheduler/scheduler.go#L706)

### 4. 一个清单文件读写卡住会拖住其他任务

**WSL 已复现。** 将一个任务的 `danlu.json` 替换为 FIFO，模拟收尾读取阻塞。随后提交的独立任务停在 `running、pid=0`，解除阻塞后才启动。所有任务的清单写入共用一把锁，调度器退出时还会等待清单更新。

建议按任务隔离清单 I/O，为任务准备和服务关停设置等待上限。回归用例应验证一个输出目录阻塞时，其他目录的任务仍能启动。 [清单写入](../internal/runner/manifest.go#L110) · [启动前写清单](../internal/scheduler/scheduler.go#L701) · [关停等待](../internal/scheduler/scheduler.go#L334)

### 5. 首次公网登录在验证服务器身份前提交密码

**文档路径确认。** README 指引用户跳过浏览器的证书警告，登录后从同一页面下载并安装根 CA。能拦截连接的攻击者可以冒充面板，获取提交的密码并替换 CA 下载。

建议让首次接入和换 CA 都通过已验证的 SSH 通道获取 CA，再安装证书并登录。面板里的下载入口可用于已验证连接上的设备分发。 [首次接入步骤](../README.md#L90) · [Chrome 的连接安全说明](https://support.google.com/chrome/answer/95617?hl=en-2)

### 6. 快照重跑遗漏混合目录中的 Git 忽略文件

**WSL 已复现。** Git 跟踪 `data/config.json`，通过 `.gitignore` 排除 `data/weights.bin`。原任务可以读取权重，快照重跑时同一条命令报文件不存在，快照备注为空。恢复逻辑只链接未归档的顶层目录，以及跳过清单里的文件。顶层 `data/` 已部分归档，Git 忽略的权重也未进入跳过清单。

建议以归档文件为准，在混合目录内补齐依赖，并说明哪些文件来自当前工作目录、哪些文件缺失。回归用例应同时检查旧配置内容、权重可读和回退来源提示。 [Git 文件枚举](../internal/snapshot/snapshot.go#L267) · [恢复补齐](../internal/snapshot/restore.go#L194)

## P2 · 后续修复

### 7. 并发请求能超出登录限速

**WSL 已复现。** 将 `max_failures` 设为 2 后，同一 IP 并发提交 21 个错误密码，21 个请求均执行密码校验并写入失败审计。锁定检查位于 bcrypt 之前，校验后的计数读取与写回分成两条 SQL。

建议在执行 bcrypt 前限制并发，并原子更新失败计数和锁定状态。 [登录入口](../internal/auth/auth.go#L275) · [失败计数](../internal/store/store.go#L734)

### 8. 日志末尾有残缺 UTF-8 时，SSE 无法结束

**WSL 已复现。** 在已结束任务的日志末尾添加一个三字节字符的前两个字节，随后从 tail 返回的偏移打开 SSE。日志读取保留残缺字节等待下次补齐，偏移始终到不了文件末尾，客户端收不到 `end`，页面会继续显示「实时」。

建议运行期间继续等待字符补齐，任务结束时消费或跳过残缺字节后发送 `end`。 [UTF-8 处理](../internal/logs/logs.go#L59) · [SSE 结束条件](../internal/api/api.go#L691)

### 9. 新建任务无法保留「不使用 conda」

**Chromium 已复现。** 模拟 `base` 和 `training` 两个环境，在 390px 新建表单选择「不使用 conda」，表单自动回到 `training`。默认值逻辑把用户显式选择的空值当作初始值，提交时会带上用户刚取消的环境。

建议仅在初始化时应用默认值，之后保留用户选择。 [默认值逻辑](../web/src/pages/NewJob.tsx#L84) · [表单选项](../web/src/pages/NewJob.tsx#L221)

### 10. 桌面升级会误报正常结束的任务丢失

**代码路径确认。** 升级检查接受仍在运行的任务，以及结束时间早于重启命令发出时刻的任务。升级前运行、服务重启期间正常完成的训练会被判为接管失败，进而挡住后续服务器升级。

建议结合最终状态、退出原因和任务进程身份判断升级是否中断训练。 [升级接管检查](../desktop/src-tauri/src/ops.rs#L155)
