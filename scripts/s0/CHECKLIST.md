# Danlu v0.2.0 真机验收清单

用含 F1 的候选版走完 [DEMO.md](../../docs/DEMO.md) 第 0 节、[ROADMAP.md](../../docs/ROADMAP.md) 的六个场景和以下真机检查。记录主机、候选版、任务编号、实际结果和截图。遇到问题时保留原始现象，反馈前先检查报告和截图的敏感内容。

## 准备

1. 使用候选版的构建产物。需要从 tag 构建时，在开发机运行 `.\scripts\build.ps1`，ARM 服务器加 `-Arch arm64`。
2. 已有服务按 [README 升级](../../README.md#升级) 操作，先升级一台。核对 `danlu version` 和 `/api/me` 的版本、旧库备份和运行任务接管，再部署其余目标机。新机器走 [初始化与部署](../../README.md#部署)。
3. **上传工具包**：`scp -r scripts/s0 服务器:~/s0`。
4. **准备 Python 环境**。批量提交和采集使用 `python3` 和 `curl`。训练脚本在已有的 PyTorch 和 tqdm conda 环境运行，下文记作 `<env>`。
5. **先采集一次**：`bash ~/s0/collect.sh`，把生成的 `s0-report-<主机名>.tar.gz` 贴回来。后面有几条要求做完以后再采集一次。

提交任务时，工作目录都填 `~/s0/jobs`，conda 环境填 `<env>`。

`~/s0/jobs` 不是 git 仓库，所以快照只按扩展名收文件，看不到 commit 和 diff。第 A6、A7 条（代码快照、重跑）请用你自己的一个真实项目目录跑一遍，那里才有 git 信息。

## C. 失败日志样本（给 S1 的失败归类用）

每个任务失败以后，把 `~/.danlu/logs/<id>.log` 和面板上显示的失败原因一起贴回来。日志里有不想外传的路径或数据，替换掉就行，报错的那几行保持原样。

| # | 命令 | 预期 |
|---|---|---|
| C1 | `python fail_cuda_oom.py` | `torch.OutOfMemoryError: CUDA out of memory` |
| C2 | `torchrun --nproc_per_node=2 fail_cuda_oom.py` | 两个 rank 各报一次显存不足 |
| C3 | `python fail_exception.py` | `TypeError`，调用栈有三层 |
| C4 | `torchrun --nproc_per_node=2 fail_nccl.py` | 1–2 分钟后 NCCL watchdog 超时 |
| C5 | 第 B4 条的日志 | `kill -9` 一个 worker 之后 torchrun 的输出 |
| C6 | 平时真实训练里遇到的任何失败 | 越多越好 |

主机内存不足（被 OOM killer 杀掉）这次不造：在共享的服务器上可能误杀别人的进程。S1 会用 cgroup 限额安全地造。

## D. 六个使用场景

| # | 怎么做 | 应该看到 | 贴回来 |
|---|---|---|---|
| D1 早上看手机 | 在空队列、至少两张可用 GPU 的机器上运行 `bash ~/s0/jobs/submit.sh morning <env>`。长任务默认跑 60 分钟，可用 `DANLU_S0_LONG_MINUTES` 调整到计划查看时仍在跑。等短任务结束后用手机打开总览 | 四个任务成功，一个归类为 CUDA 显存不足，一个仍在运行且有 tqdm 剩余时间 | 手机总览和失败详情截图 |
| D2 改了再跑 | 在手机上从 D1 失败详情点「改参数重跑」，把 `--blocks 10000` 改为 `--blocks 1`，从打开失败详情开始计时 | 30 秒内提交成功，新任务按改后的参数运行 | 耗时和新任务编号 |
| D3 排了一批 | 在空队列手动暂停后运行 `bash ~/s0/jobs/submit.sh quick-fail <env>`，看到十个编号后继续队列 | 第一个任务因 `--lrr` 快速失败。队列自动暂停，后九个仍排队，手机只收到一条带原因的暂停推送 | 队列截图和通知截图 |
| D4 写论文 | 在真实 Git 项目跑两次训练，从一个 checkpoint 的绝对路径反查任务，对比两次任务，再选择「任务快照」重跑 | 能查到命令、版本和环境差异。重跑显示原任务来源，实际在自己的 `run/<id>/code/` 执行 | checkpoint 来源、对比页和新任务编号 |
| D5 出了意外 | 按 B6 在维护时段验证机器重启。另跑一条长任务，用 `systemctl --user show danlu -p MainPID --value` 核对服务 PID 后对该 PID 发 SIGKILL | 机器重启后的旧任务归类为服务器重启。只杀 danlu 时 systemd 拉起服务，训练 PID 和进度继续。磁盘写满与 `nvidia-smi` 卡住使用 WSL e2e 证据 | 两种恢复的任务截图及接管日志 |
| D6 手机处理 | 从任务详情打开终端，执行 `ls` 和 `sleep 600 &`，用 `kill $!` 清掉该进程。用 Gboard 输中文、按 Ctrl+C、打开 htop，切到后台 1 分钟再回来 | 终端使用任务目录和环境，输入和中断可用，回前台后能接着用原会话 | 手机型号、输入法和重连结果 |
