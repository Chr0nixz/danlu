# Design System: 丹炉 Danlu

## Overview

**Creative North Star: "值班台"（The Quiet Console）**

丹炉的界面是一块安静、密集的控制台，做工对标 Vercel 控制台、Linear 和 GitHub Actions（类别标准 canon 方向，用户在两轮方向选择后主动选定）。整个画面由中性灰阶构成：页面底、面板、1px 边线、四级文字灰。颜色从不用来装饰，只用来说状态：蓝色是在跑，绿色是成功或空闲，红色是失败，琥珀是外部进程或需要注意，灰色是排队和取消。朱砂色只属于火焰标志。

密度是这个系统的底线。列表和表格优先，一行里同时给出状态图标、#编号、名称、GPU 卡号、最后一行日志、时长、结束时间和 commit；卡片只留给 GPU 这类本身就是"一台设备一块"的数据。所有数字等宽（tabular-nums），刷新时不跳。字体只用系统字体栈，不打包字体，也不从外部 CDN 加载任何资源。

深浅两套主题共用同一套语义变量，默认跟随系统，可以在设置里强制浅色或深色。日志和代码面板在两种主题下都是深色终端。明确拒绝的样子：粗圆角大卡片加橙色按钮的模板面板。

**Key Characteristics:**
- 中性灰阶 + 状态色，颜色即语义
- 状态同时用形状和颜色区分（lucide 图标）
- 反色实心主按钮，朱砂色只给火焰标志
- 系统字体栈，全局 tabular-nums
- 控件圆角 6px，面板圆角 8px，1px 边线，几乎没有阴影
- 日志和代码是深色终端，两种主题都一样
- 信息密度只能升不能降

## Colors

一套冷静的纯中性灰阶，加四个按深浅主题分别调过亮度的状态色；所有颜色都是语义变量（`--bg`、`--fg-2`、`--run` 等），通过 `@theme inline` 映射成 Tailwind 颜色。

### Primary
- **反色墨（Inverted Ink）** (`inv` / `inv-fg`)：主按钮和手机底部导航中间的"新建"块。浅色模式黑底白字，深色模式白底黑字。主动作靠明度反差而不是色相来突出。

### Secondary
- **运行蓝（Run Blue）** (`run`)：运行中的旋转弧、运行任务的进度细条、占卡 GPU 的利用率条、焦点环（`--focus`：浅色主题实色，深色主题 70% 混合）、输入框聚焦光晕（15%）、文字选区（28%）。
- **成功绿（OK Green）** (`ok`)：成功对勾圈、GPU "空闲"圆点、摘要里"有空卡"圆点、日志直播中的脉冲点。
- **失败红（Fail Red）** (`fail`)：失败叉圈、失败原因文字、失败计数、危险按钮文字、错误提示框（6% 底、30% 边）。
- **琥珀（Warn Amber）** (`warn`)：外部进程占卡（文字、圆点、利用率条）、正在取消中的运行图标、未提交改动没进快照时 commit 后的小圆点和说明、数据过期提示、警告框。

### Tertiary
- **朱砂（Cinnabar）** (`brand`)：只用于火焰标志（顶栏 24px 圆角方块和 favicon），两种主题下不变。

### Neutral
- **页面底（Page）** (`bg`)：整页背景。
- **面板（Surface）** (`surface`)：面板、顶栏、底部导航、输入框和次按钮底色。
- **衬底（Subtle）** (`subtle`)：分组标题栏、行悬停、分段控件轨道、说明框。
- **浮起（Raised）** (`raised`)：分段控件选中块；深色模式下明显亮于面板。
- **悬停（Hover）** (`hover`)：幽灵按钮和次按钮悬停底、细条轨道、骨架屏。
- **边线（Line）** (`line`)：面板边框、行分隔线、标签页底线。
- **强边线（Line Strong）** (`line-strong`)：次按钮、单选卡片、GPU 卡号小方块的边框，只读输入框，滚动条。这些靠文字就能认出来，边线不承担识别作用。
- **输入框边线（Field Line）** (`field-line`，深色 #666)：输入框、下拉框、多行输入和 GPU 张数步进器的边框。用户靠它找到能输入的地方，所以和面板底、页面底、衬底都在 3:1 以上（WCAG 1.4.11），两种主题下都是 3.1–3.5:1。
- **文字四级** (`fg` / `fg-2` / `fg-3` / `fg-4`)：正文与标题 / 次要值 / 标签、编号、时长、占位符 / 分隔斜杠和空闲细条。
- **终端底（Terminal）** (`term-bg` / `term-fg`)：日志和代码面板，两种主题都用；文字选区为运行蓝 35%。ANSI 16 色按深色背景调亮（见 sidecar）。
- **终端红（Terminal Red）** (`term-fail`，即 ANSI 红 #ff7b72)：终端面板里的报错框（日志或代码读取失败），两种主题都用。页面的失败红在浅色主题下是 #cd2b31，放在终端底上只有 3.6:1。

### Named Rules
**The Color-Is-Status Rule.** 颜色只表达状态或注意事项。没有状态含义的地方一律用灰阶；不加装饰色、不加渐变、不给分区上色。

**The One Flame Rule.** 朱砂色 `brand` 只出现在火焰标志上。主按钮用反色墨，绝不用朱砂或任何橙色。

**The Paired Theme Rule.** 新增颜色必须作为语义变量同时定义浅色和深色两个值，并同时写进 `prefers-color-scheme: dark` 块和 `[data-theme="dark"]` 块；组件里只引用变量，不写裸色值（终端面板除外）。

## Typography

**Display Font:** 无（这个系统没有展示字级）
**Body Font:** 系统无衬线栈（ui-sans-serif, system-ui, Segoe UI, PingFang SC, Microsoft YaHei UI …）
**Label/Mono Font:** 系统等宽栈（ui-monospace, SFMono-Regular, Cascadia Mono, Menlo, Consolas …）

**Character:** 不打包任何字体，中文走系统黑体，读起来就是操作系统本身的控制台。字级很窄，层级主要靠字重（400 / 500 / 600）和四级文字灰拉开，而不是靠字号。

### Hierarchy
- **Headline** (600, 20px, 28px, -0.025em)：任务详情页的任务名，全站唯一的大标题。
- **Title** (600, 18px, 28px)：页面标题（任务、新建任务、设置、登录）。
- **Body** (400–500, 14px, 20px)：任务名（500）、输入框文字、中号按钮、标签页。
- **UI** (400–600, 13px, 20px)：系统的主力字级（`text-ui`）。导航、分组标题、摘要、GPU 卡号、表单标签、小按钮、提示框。
- **Label** (400, 12px, 16px)：说明文字、时长、相对时间、GPU 指标、最后一行日志。
- **Mono** (400, 12.5px, 1.6)：终端面板、路径、命令、环境变量、commit（12px）、最后一行日志（12px）。
- **Micro** (11px)：GPU 卡号小方块（等宽）、快捷键提示、手机底部导航标签、终端会话标签上的开启时间、手机摘要里的"24h"；证书指纹用 11.5px 等宽。不出现比 11px 更小的字。

### Named Rules
**The Tabular Rule.** 全局 `font-variant-numeric: tabular-nums`。任何会刷新的数字（利用率、显存、时长、计数）都必须等宽对齐，不能在刷新时抖动。

**The System Stack Rule.** 只用 `--font-sans` 和 `--font-mono` 两个系统栈。不引入网络字体，不打包字体文件。

**The Narrow Ramp Rule.** 字号不超过 20px。需要强调时先用字重和文字灰，而不是加大字号。

## Layout

内容区最大宽 1200px 居中；内边距手机 16px、≥640px 24px；页面纵向 16px / 24px。页面内区块间距 16px（≥640px 时 20px）。间距用 4px 基准的 Tailwind 刻度，常用 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24px。

- **顶栏**：粘性，高 48px，面板底加底边线。依次是火焰标志、"丹炉"、斜杠、主机名、下划线式导航（总览 / 资源 / 任务 / 设置），右侧主按钮"新建任务"带 `N` 快捷键提示。
- **首页**：状态摘要一行（运行 / 排队 / 24 小时内失败 / 空闲卡数 / 实时；手机上"24 小时内"写成 11px 的"24h"，摘要仍放得下一行）→ GPU 面板一排（≥1024px 四列，≥640px 两列）→ 一个面板里的分组任务列表（运行中、排队、最近完成），分组标题栏高 36px、衬底色 → 主机资源面板（CPU 和内存左右两栏：当前值、细条、最近 1 分钟曲线）。主机资源在手机和电脑上都排在任务列表后面：首屏要回答的是任务跑完没有、跑到哪了、卡空不空，CPU 曲线不在其中，放在 GPU 下面会把失败的任务挤出首屏。主机资源面板标题栏右侧有「资源详情」链接，桌面显示文字和箭头（36px 标题栏内），手机只显示箭头但点击区是 44 × 44px，不增加首页请求。页面有一个读屏可见的 h1"总览"，GPU 区是一个带读屏标题的 section。手机上摘要行只放四个计数（运行 / 排队 / 失败 / 空闲），正好一行；「预约 GPU」挪到顶栏右侧（见 GPU 预约）。24 小时内有失败时，手机摘要下面多一行点名最近挂掉的任务：12px 失败图标、`fg-3` #编号（"最近失败"只给读屏）、任务名（500 字重，先截断）、失败原因（失败红，最多占四成宽）、右侧多久前和箭头，整行 44px 点击区直达详情；两三个任务在跑和排队时最近完成的列表已经在首屏以下，只看"9 失败"答不出挂的是哪个。电脑上最近完成的列表就在首屏，不显示这一行。
- **资源页**：信息密集的看板，按用户的三个问题排，不按 /proc 的采集顺序：**页头 → GPU 表 → 指标墙（5 张指标卡）→ 明细（CPU 核心 / 内存构成 / 功耗与温度，存储 / 网卡）→ 进程**。1440 × 900 下第一屏看完 GPU、全部曲线和第一排明细，整页约 1.7 屏。
  - **页头**：标题、系统/内核/运行时长；右侧是数据新鲜度（绿点 + "N 秒前 · 每 2 秒采样"，超过 10 秒变琥珀，手机上和标题同一行）和四档范围（1 分钟 / 5 分钟 / 15 分钟 / 1 小时）。范围可分享（URL），也记住上次选的档位（localStorage），非法 range 静默修正地址栏；切档用 keepPreviousData 保留上一档曲线，不闪空态；曲线刷新间隔随档位走（3 / 5 / 10 / 20 秒）。新鲜度按快照自己的采样时间算；主机数据一次都没采到时只显示 GPU 表和一句说明，不画一屏 0。轮询失败时保留上一份快照的全部面板，顶部琥珀横幅写明"显示的是 N 秒前的快照"并给重试；只有首次加载失败才整页报错（重试 + 回到总览）。
  - **手机摘要行**：只在 <640px 显示，放在 GPU 表上面，一行行流式排 CPU、内存、负载、交换、功耗（CPU 读不到时写「GPU 功耗」）、网络、磁盘和「磁盘空间 偏低」。手机首屏只放得下页头和 GPU，靠它把这些数留在首屏；电脑上指标卡本来就在第一屏，不显示这一行。
  - **GPU 表**：标题栏右侧是绿点"N / M 张卡空闲"和型号（混装时型号写在每张卡的卡号下面）。≥1024px 每张卡一行、带列头：卡、利用率（细条 + 数）、显存（细条 + 已用/总量）、温度、功耗/上限、风扇、核心/显存频率、P-State、占用；细条颜色跟首页一样随占卡状态（任务蓝、外部琥珀、空闲 `fg-4`）。<1024px 每张卡两行（卡号 + 占用；细条和其余指标流式排）。占卡叙事与首页同一套：运行中的任务带蓝色旋转弧并链接，外部进程按任务/用户合并、显存可见、单个进程写出 pid、别的任务的进程链接过去；查询失败保留面板外框加 Alert，空态区分"读取失败，无法判断占用"和"没有检测到 GPU"。
  - **指标墙**：CPU、内存、磁盘、网络、功耗 5 张等高的卡，≥1280px 一排 5 张，640–1279px 3 + 2，手机两列（功耗占满一行）。每张卡同一个结构：标题和容量（64 核、512 GB、3 块物理盘、4 个网卡、GPU 上限）→ 20px 当前值（数字和单位分开，单位小一号灰字）→ 第二个值 → 区间统计 → 小面积图（桌面 56px、手机 40px）和起止时间。有两条线的卡，当前值和第二个值前各有实线/虚线小图例，对应图上的两条线：内存是已用/交换，磁盘是读/写，网络是接收/发送，功耗是 GPU/CPU 封装（CPU 读不到时第二行写"CPU 封装 读不到"，图上不留那条线）。CPU 卡的第二个值是负载（超过核数变琥珀）。磁盘容量偏低写在磁盘卡右上角（琥珀），不染在读写速率上，也不单独占一行把卡撑高。区间统计是"平均 · 峰值"，速率写成"峰值 读 460.0 写 120.0 MB/s"（单位相同只写一次），项之间只留空隙，折行时不会把圆点挂在行首。

- **断点**：640px（sm）、768px（md）、1024px（lg，任务行从两段换成固定列）、1280px（xl，只用于任务行名称列加宽）。

**The Density Floor Rule.** 信息密度只能升不能降。这是用户明确的回归判据：任何改版如果让一屏可读的任务、GPU 或字段变少，就是退步。

### 首页速度

定版标准是在 Chrome 的 Fast 4G 节流下，首页 2 秒内能看到 GPU 和任务（ROADMAP.md 第 8 节）。2026-11-05 在 `dev-5fbb10b` 上测了一次，条件如下：
- **服务。** 开发机（i7-14700HX）的 WSL 里起本地 CA 模式的服务，和真机一样走 TLS 和 HTTP/2。4 张假卡中 1 张被外部进程占用，2 个任务在跑、1 个排队，另有 8 个已结束的任务，其中 2 个失败。
- **浏览器和节流。** Chrome 156 无头模式，390×844 手机视口。通过 CDP 套用 DevTools 的 Fast 4G 预设：延迟 165 ms，下行约 8.1 Mbps，上行约 1.35 Mbps。
- **怎么算。** 计时从开始导航算起，到 GPU 区和任务列表都渲染出数据为止，取检测到之后的下一帧。冷启动用全新的浏览器上下文：缓存为空，连接新建。热缓存是在同一上下文里再打开一次。每组 7 次，取中位数，括号里是最慢的一次。

| 情况 | 首次绘制 | GPU | 任务 | 两者都出现 | 传输 |
|---|---|---|---|---|---|
| 冷启动 | 576 ms | 759 ms | 802 ms | **802 ms**（824） | 143 KB |
| 热缓存 | 220 ms | 404 ms | 416 ms | **416 ms**（430） | 18 KB |
| 冷启动，CPU 降速 4× | 724 ms | 952 ms | 1081 ms | **1081 ms**（1277） | 143 KB |
| 热缓存，CPU 降速 4× | 292 ms | 497 ms | 570 ms | **570 ms**（597） | 18 KB |

冷启动分三段，一段接一段：
1. HTML，约 190 ms；
2. 首屏的 JS 和 CSS，gzip 后共 126 KB，其中主包 78 KB，约 330 ms；
3. 首页的 8 个接口，经 HTTP/2 并发，约 200 ms。

**几点说明：**
- DevTools 的节流只给每个请求加延迟，不模拟 TCP 和 TLS 握手。真实 4G 上首次连接大约还要多 2 个往返，约 330 ms。
- 4× CPU 降速只是近似中端手机，不是真机。

把这两点都算上，冷启动仍在 1.5 秒以内，不用再做优化。以后改版时，如果首屏包或首页的接口数明显变多，按同样的条件再测一次。

## Elevation & Depth

系统是平的。层次靠背景色阶（页面底 → 面板 → 衬底 / 浮起）和 1px 边线表达，静止的面板没有阴影。阴影只出现在真正浮起来的东西上，而且都很轻。

### Shadow Vocabulary
- **分段选中块** (`box-shadow: 0 1px 2px rgb(0 0 0 / 0.08)`)：分段控件里被选中的一格。
- **浮层菜单** (`box-shadow: 0 8px 24px rgb(0 0 0 / 0.12)`)：工作目录自动补全下拉、详情页的更多操作菜单、确认框（确认框下面另有 40% 黑色遮罩）。
- **终端浮钮** (`box-shadow: 0 4px 12px rgb(0 0 0 / 0.4)`)：日志面板里"回到底部"按钮。
- **标签页底线** (`box-shadow: inset 0 -1px 0 var(--line)`)：下划线标签页的轨道线，不是投影。

### Named Rules
**The Flat-At-Rest Rule.** 面板、卡片、列表静止时只有边线没有阴影。只有覆盖在其他内容之上的浮层才允许投影。

## Shapes

圆角克制而分级：控件 6px（按钮、输入框、分段控件轨道、提示框、标志方块），面板 8px（面板、GPU 面板、终端、代码浏览器），小方块 4px（GPU 卡号、分段选中块、终端工具栏按钮、快捷键提示），圆点和细条全圆。所有容器用 1px 实线边；只有空状态的说明框用虚线边。进度细条高 4px。

**The Two Radii Rule.** 控件 6px、面板 8px，不出现更大的圆角。

## Components

### Buttons
干净、低调，靠明度说话。
- **Shape:** 控件圆角 (6px)；中号高 36px、左右 14px、14px 字；小号高 32px、左右 10px、13px 字；图标按钮 36 / 32px 见方，图标 16px。手机（<640px）上两种尺寸都是 44px 高，图标按钮 44px 见方，内边距和字号不变。
- **Primary:** 反色墨实心 (`inv` 底、`inv-fg` 字)，500 字重。悬停透明度 85%，按下 75%。
- **Hover / Focus:** 背景、边线、文字、透明度 150ms 过渡；键盘焦点是 2px 运行蓝外框（`--focus`），偏移 2px：浅色主题用实色，在页面底、面板和衬底上都在 4.5:1 以上；深色主题用 70% 混合。禁用为 45% 透明度。加载时左侧换成旋转图标。
- **Secondary:** 面板底、强边线、主文字色，悬停变 `hover` 底。
- **Ghost:** 无底无边，`fg-2` 文字，悬停 `hover` 底并变 `fg`。
- **Danger:** 次按钮外形、失败红文字，悬停边线和底色带 8% 的失败红。

### Chips
- **GPU 卡号：** 18px 高的小方块，4px 圆角，强边线，11px 等宽 `fg-2`，多张卡紧贴并排（间距 2px）。
- **代码版本标签：** 分支、commit 和"有未提交的改动"都用中性小标签。代码页里有快照，改动已经保存，不需要提醒。
- **Commit：** 7 位短哈希，12px 等宽 `fg-2`；有未提交改动时后面跟 6px `fg-3` 灰点（读屏读"有未提交的改动"）。代码用 rsync 同步过来，工作区几乎总有改动，进了快照就是常态，不该用琥珀；只有改动没进快照（任务已经开始、快照没拍成）时圆点才是琥珀（读屏读"没有进快照"）：只凭 commit 找不回当时的代码。任务行和详情页里的 commit 都是链接，直达这个任务的代码快照（`/jobs/:id?tab=code`），悬停变 `fg` 加下划线。链接的点击区向四周撑出一圈（左右各 8px、上下各 10px，36px 高），不改变排版也不越出任务行，免得在手机上点成整行。详情页的"代码版本"标签后面写明"有未提交改动"（和标签同色），触屏上看不到悬停提示也能知道圆点的意思；没进快照时改用琥珀字"改动没进快照"，详情标签里写明只凭 commit 找不回当时的代码。重跑页代码来源卡片里的"有未提交改动"也是 `fg-3`，两边代码不一样时由下面的琥珀提示框说明。

### Cards / Containers
- **Corner Style:** 面板圆角 (8px)。
- **Background:** `surface`；分组标题栏 `subtle`。
- **Shadow Strategy:** 无（见 Flat-At-Rest Rule）。
- **Border:** 1px `line`；内部行之间也用 1px `line` 分隔。
- **Internal Padding:** GPU 面板 12px；列表行 10px × 16px；表单行 16px × 20px。

### Inputs / Fields
- **Style:** 36px 高（手机 44px），面板底，1px 输入框边线（`field-line`，和背景 3:1 以上），6px 圆角，左右 12px，14px 字；占位符 `fg-3`。只读的输入框用衬底色、强边线（`line-strong`）和 `fg-2` 文字，悬停和聚焦时边线不变，看起来不像能编辑。路径、命令、环境变量输入用 12.5px 等宽。GPU 张数步进器相当于数字输入框，边线和输入框一样。
- **Focus:** 悬停边线变 `fg-3`；聚焦边线也是 `fg-3`，外加 3px 运行蓝 15% 光晕。150ms 过渡。
- **Error / Disabled:** 禁用 50% 透明度。字段错误在字段正下方用 12px 失败红文字加 14px 警示图标说明，字段边线变失败红 60%，提交时焦点移到第一个出错的字段；不用浏览器自带的必填气泡（登录页、新建页和设置页的改密码都一样），搜索框也不用浏览器自带的清除图标。只有服务端返回的错误放在表单底部的失败提示框里。
- **工作目录补全：** 聚焦时不展开，输入或按 ↓ 才展开子目录列表，Esc 收起；校验失败时焦点落在这里，展开的列表不能盖住错误说明。
- **单选卡片：** 少数几个、每项需要两行说明的单选（重跑时的代码来源）用并排的卡片，和指定 GPU 的卡片同一套样子：6px 圆角、强边线，选中时 `fg` 边线加 1px `fg` 描边、衬底色和对勾；第一行 13px / 600 标题，第二行 12px `fg-3` 说明，最多两行。底下是原生单选框，方向键和禁用交给浏览器，键盘焦点框画在卡片上。
- **新建表单：** 用键盘进来时焦点直接落在第一个要填的字段上（新建是工作目录，重跑和复制是命令），触屏上不自动聚焦。提交栏吸在视口底部（手机上在底部导航上方）。没提交的内容存在 sessionStorage 里，刷新或被浏览器回收标签页后恢复，表单上方用中性提示写明，并给"重新填写"。
- **Labels:** 每个控件都用 `<label for>` 关联标签，说明文字用 `aria-describedby` 关联；组合控件（分段按钮 + 步进器）是以标签命名的 group。

### Navigation
- **桌面顶栏导航：** 13px，未选中 `fg-3`，悬停 `fg`；选中 500 字重 `fg`，下方 2px `fg` 色下划线压住顶栏底边。
- **页内标签页：** 同一套下划线语言，高 40px（手机 44px）、14px；焦点环画在标签里面，不会被可横向滚动的轨道裁掉。终端页的会话标签用同一套键盘约定。
- **分段控件：** 32px 高（手机 44px）的衬底轨道，选中格是浮起色 + 轻阴影 + 1px `line` 描边（浅色主题下白块叠在浅灰上，没有描边分不清）；用于筛选和小范围切换，选项里可以带状态图标。语义上是单选组，标签页是 tablist，两者都只有选中项能 Tab 到，左右方向键和 Home / End 切换。
- **手机底部导航：** 见 Layout。图标 20px，标签 11px / 500；选中 `fg`，未选中 `fg-3`。
- **更多操作菜单：** 一行放不下、又不常用的操作收进一个 44px 的 `⋯` 次按钮。展开的菜单右对齐、面板底、1px `line` 边、6px 圆角、浮层阴影，每项 44px 高、14px `fg-2` 字、16px `fg-3` 图标，悬停和键盘焦点都是 `hover` 底。打开时焦点落在第一项，↑ ↓ Home End 移动，Esc 关闭并把焦点还给按钮，点外面、Tab 离开或点了某一项都会关闭。目前只用在手机的任务详情页。任务页的状态筛选在手机上铺满一整行、只写文字不带图标，六个状态都在屏幕里。

### 状态图标（Signature）
所有状态都用 16px 的 lucide 图标，形状和颜色同时区分，色盲也能读：
- 排队：灰色虚线圈 (`fg-3`)
- 运行：蓝色旋转弧 (`run`，匀速 1.6s 一圈)；正在取消时变琥珀
- 成功：绿色对勾圈 (`ok`)
- 失败：红色叉圈 (`fail`)
- 取消：灰色斜杠圈 (`fg-3`)
- 外部进程占卡：琥珀色 6px 圆点 + 琥珀文字
- GPU 预约的卡：灰色 lucide 锁（`fg-2`）+ "预约 #3 · 到 15:30"。预约不是任务状态，不占用状态色

作为分组标题时（如"最近完成"）图标可以退成中性灰。图标默认带读屏能读出的状态名（`role="img"`）；旁边已经写着状态文字时（摘要、分组标题、筛选、状态标签）标成装饰，免得读两遍。任务状态变化时，除了整行闪一下，还通过全局唯一的读屏播报区（`role="status"`，polite）读一句"任务 #5 名字：成功"，同一轮里的几条合成一句。

### 任务行（Signature）
Linear 式的单行：状态图标、#编号（`fg-3`）、任务名（14px / 500）、GPU 卡号、运行任务的 40px 进度细条、最后一行日志（12px 等宽）、时长、结束时间、commit。失败的行写"失败原因 · 报错行"：服务端从日志末尾找最后一条像报错的行（Python 异常、torchrun 的 `[rankN]:` 异常、Killed、段错误，以及命令这一层的报错：bash 的命令没找到、文件不存在、没有权限，python 打不开文件，包装脚本进不了工作目录或激活不了 conda），跳过 torchrun 的 ChildFailedError 汇总；bash 报错里任务命令脚本的绝对路径（`…/run/8/cmd.sh: line 1:`）显示时去掉，原因不被挤出行外；找不到时用最后一行输出。整行可点：名字是链接，用 `::after` 铺满整行，commit 和取消按钮浮在上面单独可点；键盘焦点框画在整行上。任务列表对读屏是列表，时长和结束时间各自带读屏说明。对比选择模式下整行变成勾选框的点击区，名字和 commit 不再是链接，点到行不会离开页面。悬停整行变衬底色；运行中的行在悬停时才显示取消按钮（触屏常显）。**状态变化时整行背景闪一次**：1.2s ease-out，前 15% 保持新状态颜色 14% 的底色再淡出；成功闪绿、失败闪红、取消闪灰、其余闪蓝。

首页和任务页每个任务行右侧常显中性的复制图标，与标星、取消操作并列；电脑上点击区 32px，从名称列调配宽度，保留卡号和最新输出列的空间。手机上行尾只留一个 44px 的操作，不额外撑高任务行：运行和排队的行是取消，已结束的行是复制。任务页的对比选择模式下不显示复制图标（点了会离开页面、丢掉已选的任务），但留出位置，列宽不跳；标星不在手机的行上点，只显示星标，标星和取消标星在详情页的更多操作里。复制只预填新建表单，保留原名，提交后是独立任务，不记录“重跑自”。复制页不显示原任务的失败说明或代码比较；现有重跑入口继续使用自己的名称后缀和来源关系。

### 任务详情操作栏
每种状态只有一个主操作：运行和排队的任务是"取消任务"（危险按钮，按钮上写全"取消任务"，不写"取消"），已结束的任务是"重跑"（反色墨），失败的写成"改参数重跑"，和代码无关的失败（服务器重启、被外部终止、收到信号、NCCL 出错）写成"原样重跑"，和失败说明里的建议、重跑页默认选中的快照说同一件事；正在取消的任务没有主操作，重跑退成次按钮。电脑上所有操作都露在外面，分两级：标星、结束提醒、终端、和…对比、复制任务是幽灵按钮（运行中的任务再加一个重跑），实验记录链接和主操作带边框，主操作排在最右。手机上一行只放主操作和实验记录链接，都是 44px 高，其余（标星、改名、重跑、复制任务、终端、和…对比）收进行尾的更多操作菜单；标星的任务在标题后跟一个 16px 的实心星。

改名就地进行：电脑上任务名后面跟一个 32px 的幽灵铅笔按钮（`fg-3`），手机上在更多操作里。点开后标题行换成一个输入框加"保存"（反色墨）和"取消"，手机上三者都是 44px 高、排在一行；文字先全选，Enter 保存，Esc 或"取消"放弃，名字没变就直接退出，出错时留在原地显示原因。已经启动过的任务在输入框下方用 12px `fg-3` 写明输出目录和 DANLU_JOB_NAME 不跟着改。不用确认框：改名可以随时改回来。

### 失败说明
任务详情页状态栏下方的失败红框，第一行就是报错行（12.5px 等宽），退出码已经在状态栏里，不再重复；被外部终止、启动失败这类退出码以外的原因另起一行。和代码无关的失败反过来：原因本身就是答案，写在第一行，后面是"中断前的最后一行输出"。找不到报错行时只标"最后一行输出"，不写"没有找到报错行"：那一行常常就是原因，不该先否认它。接着按服务端的失败分类（`fail_kind`）给一句下一步，用主文字色：显存不足建议减小 batch size 或多申请一张卡，主机内存不足建议减少 num_workers，NCCL 出错建议先原样重跑，Python 异常建议按报错行改代码，命令没找到直接说出这次用的 conda 环境（或"没有选 conda 环境，只在 PATH 里找"）并建议选上装了它的环境或写完整路径，命令不能执行建议加执行权限，conda 激活失败建议检查环境名，进不了工作目录建议确认代码已同步，服务器重启和被外部终止建议用快照原样重跑，启动失败建议检查工作目录、conda 和 ~/.bashrc；只给建议，不替用户断定原因，没法归类的（只有退出码）不写。红框末尾是"看日志末尾"，切到日志标签并滚到日志面板。清理残留进程等运行备注单独用中性提示显示，成功和取消的任务也能看到。重跑页标题下方用失败红写出原任务为什么失败。

### 任务备注、静默和日志搜索

详情标题下用中性文字就地编辑备注；手机上没写过备注时不占这一行，"写备注"收在更多操作里。任务行沿用原有行高，完成任务用备注首行替换输出摘录，失败原因保留。静默任务在运行状态旁加琥珀色提示，详情提供看日志、终端和取消三个入口：写成一行文字链接，不撑高提示框，"取消任务"用失败红并单独靠右。结束推送在桌面使用中性铃铛，手机入口放在更多操作。资源画像放在详情和对比的现有表格区。

搜索从日志工具栏打开，桌面是聚焦的结果面板，手机从底部打开半屏面板。命中文字用中性色高亮，结果可键盘或触屏选择。定位时保持日志的终端配色和起始命中行，工具栏可跳到相邻命中或回到日志末尾。

### 重跑的代码来源
重跑页第一行是"代码版本"：两张单选卡片，"现在的工作目录"和"任务 #N 的快照"，第二行各自写出分支、7 位 commit 和"有未提交改动"（琥珀），选之前就看得出两边是否一样；快照不可用时那张卡片禁用并写明原因。默认值跟着失败分类走：服务器重启、被外部终止、收到信号、NCCL 出错这类和代码无关的失败默认用快照原样重跑，其余默认用工作目录现在的代码（多半刚改过）。选了工作目录且代码和快照不同时，表单上方仍有琥珀提示列出差别。

### 确认框
只用于不可恢复的操作（取消任务、关闭终端、吊销设备令牌）。原生 `<dialog>`：面板底、1px `line` 边、8px 圆角、浮层阴影、40% 黑色遮罩；宽 420px，手机上贴着底部（离底 16px 加安全区），拇指够得到。标题 14px / 600 写成问句（"取消任务 #5？"），正文写清后果：运行中的任务写已运行多久、进程会被结束且不能恢复、日志和代码快照会保留；排队的任务写排在第几位。底部是衬底色按钮栏，左边是不造成损失的按钮（"继续运行" / "保留排队"），焦点默认落在它上面；右边是危险按钮。Esc 或点遮罩关闭，出错时留在框里显示原因。不用浏览器的 `confirm` 和 `alert`。

### 页面出错
页面渲染出错时只把出错的部分换成说明，不让整个面板白屏。主内容区单独兜底，顶栏和底部导航照常能用；顶栏或登录页本身出错时整页兜底，居中一块 420px 宽的面板。说明是一块面板：14px / 600 标题，13px `fg-3` 说明，非页面文件的错误下面用 12px 等宽 `fg-2` 写出原始报错，最后是"重新加载"（反色墨）和"回到总览"（次按钮，已经在总览时不显示）；整块是 `role="alert"`。换到别的页面时清掉错误。

页面文件加载失败（多半是丹炉刚升级，开着的标签页还按旧文件名去要）时先自动刷新一次，只显示一个转圈；10 秒内已经刷新过还失败，才显示"页面没能加载"和原因（刚升级、服务正在重启或网络断了），不来回刷新。

### GPU 面板（Signature）
桌面每张卡一块面板：第一行 "GPU n"（13px / 600）、型号（混装时才显示）、温度和功耗；中间利用率和显存两组"标签 + 数值 + 4px 细条"；底部隔一条边线写占卡者（运行中的任务链接、琥珀色外部进程，或绿色"空闲"）。任务分到了卡、卡上却没有它的进程时，任务链接下面加一行 12px `fg-3`"卡上暂无该任务的进程"（GPU 数据报错时不写）；别的任务的进程跑到这张卡上时，琥珀色写"#任务号 的进程 pid · 显存"并链接到那个任务，图形进程写"图形进程"。同一个任务的多个进程合成一行（"#56 的 24 个进程 · 显存合计"），外部进程按用户合成一行，pid 列在悬停提示里：EGL 渲染一个任务在一张卡上就能有几十个进程。细条颜色跟随占卡状态：任务蓝、预约 `fg-3`、外部琥珀、空闲 `fg-4`。被 GPU 预约收下的卡在占卡者位置写一行灰色"锁 + 预约 #3 · 收卡中 / 到 15:30 / 手动释放 · 用途"（用途最先截断）；这张卡上的外部进程多半是用户自己的任务，改用 `fg-2` 文字和 `fg-3` 圆点，不标琥珀，别的丹炉任务跑过来的进程仍是琥珀。手机端改为每卡真正的一行（约 40px）：卡号方块（和任务行里的卡号同一个样子）、36px 利用率细条和数、占卡者（吃掉剩余宽度，任务名先截断；"卡上暂无该任务的进程"缩成名字后面的"· 未见进程"）、紧凑显存（"4.0/24GB"）；温度不进这一行（390px 宽时会把任务名挤到只剩一两个字，温度在电脑面板和资源页）；一张卡有多个占卡者时只有这张卡变高，混装时型号另起一行。四张卡占 160px 上下，运行中和失败的任务仍在首屏。

### GPU 预约
首页摘要行最右边有幽灵小按钮"锁 预约 GPU"（只在有 GPU 时出现，负外边距收回，不把摘要行撑高）；手机上四个计数已经占满摘要行，按钮换成顶栏右侧的 44px 锁图标（名字在 aria-label 里），只在总览出现。有预约时，GPU 面板和任务面板之间多一个"GPU 预约"面板：36px 衬底标题栏（锁、标题、个数，电脑上右侧一句"预约收下的卡不分给丹炉任务"），每个预约一行：锁、"预约 #n"、已收卡号方块、状态（"收卡中 1/2 · 已等 25分" / "等 GPU 2 · 已等…" / "已就绪 · 到 15:30（还剩 2小时59分）" / "已就绪 · 手动释放前一直保留"），用途在下一行 12px `fg-3`；右侧幽灵小按钮"复制环境变量"（复制 `CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=…`，只在已就绪时出现）、"延长 1 小时"（只对定时预约）、"释放"（确认框，说明卡会交还给丹炉）。手机上按钮换到第二行。没有预约时整个面板不出现。预约对话框是宽对话框：按张数（步进器）/ 指定卡号（与新建任务共用的卡片选择器，被预约的卡写"预约 #n"）、自动释放分段（1 小时 / 3 小时 / 8 小时 / 自定义 / 不自动，自定义是 96px 宽的小时数输入框）、用途输入框；空闲卡不够时琥珀色一句说明会先收下能收的卡。

### 终端面板（Signature）
日志和代码在两种主题下都是深色终端（`term-bg`），8px 圆角，40px 高的工具栏（白 10% 分隔线，按钮悬停白 10% 底）；手机上工具栏 44px 高，搜索、换行、下载都写出文字，只有多出"上一个 / 下一个命中"放不下时才只留图标。文字 12.5px 等宽、行高 1.6、tab 宽 4。直播时左上角绿色脉冲点。ANSI 颜色用为深色背景调亮的一套（sidecar 里有完整取值）。日志或代码读取失败时，报错框放在终端底里，用终端红（`term-fail`，8% 底、30% 边），不用页面的失败红。日志框从自己的位置铺到视口底部（手机上让出底部导航和安全区），最新几行始终在首屏里，底边不落到底部导航后面；最小高度电脑 320px，手机 120px。手机上首屏里连 120px 都放不下（上面有很长的失败说明），或者正在定位浏览（跳到报错、搜索命中）时，换成高的一档：滚到日志面板后正好占满标签页以下的屏幕。为了让手机上的日志框不落到下限，详情页手机上的操作栏只占一行，关键信息条是三列两行。在跑的任务最后一行是进度条时，关键信息条底下多一整行进度，和任务行同一套写法：12px `fg-3`"进度"、运行蓝细条（手机 40px，和任务行一样；电脑 96px）、"剩 N"、压缩过的 tqdm 行（等宽 `fg-2`，放不下截断），列表里看到的"跑到哪了"点进来还在；占满一行，不挤三列两行的格子。自动换行只在放不下时断开长串，不把 "100/100" 这类数字拆开。代码浏览器左侧有行号（`#7a7a7a`，在终端底上 4.6:1，不可选中），和 traceback 里的行号对得上。电脑上左侧是文件树（目录按钮带 `aria-expanded`，选中的文件带 `aria-current`）；手机上文件树换成一个 44px 的系统下拉选择，列出完整路径，代码紧接在下面，并去掉代码区顶上重复的文件名条，打开代码标签页就能看到代码。

### 设置页

按分组拆成子页面 `/settings/<分组>`：概览、调度与告警、数据保留、面板偏好、安全与登录、手机与证书、操作记录，每组可以直接链接。`md` 及以上左侧是 176px 宽的分组导航（选中项是中性的 hover 底色加粗，不用品牌色），右侧是内容；手机上导航换成顶部的原生下拉框，七个分组一行放不下。切换分组后焦点移到内容区开头。

每个卡片是一个独立的表单，底栏右边是"保存"（没改动时禁用），左边是"已保存，立即生效"的状态。服务端设置只提交改了的项，范围检查也只查改了的项。0 表示关闭的项在数值前有"开启"复选框，关闭时输入框置灰但不隐藏。面板上改过的项在行下方写"面板上改过，config.toml 里的值（…）不生效 · 恢复"，点恢复后保存回到配置文件的值。会删数据的改动（收紧保留策略）先预览，确认框列出会清理的任务；会立即见效的副作用（调高暂停线导致队列暂停、调短终端保留时长）在行下方写明。

面板偏好分两种：主题、日志和终端字号只存在当前浏览器（跟屏幕有关），改了立即生效，不需要保存；新建任务的默认值、每页条数、日志默认换行和资源页告警阈值存在服务器上，手机和电脑共用。"结束提醒"不再记住上次的勾选，默认值在面板偏好里设。

### 快捷键
`N` 新建任务（顶栏按钮内提示），`/` 搜索任务（在任务页聚焦搜索框，在其他页面先跳到任务页；搜索框内提示，`Esc` 清空），`J` / `K` 在总览和任务页移到下一个、上一个任务（焦点落在行的链接上，`Enter` 打开），`Ctrl/⌘ + Enter` 提交新任务（焦点不在表单里也有效，提示按系统写 `⌘` 或 `Ctrl`），`?` 打开快捷键一览，设置页也有一份。确认框开着时都不响应。快捷键提示是 20px 高、11px、当前色 25% 边框的小框，在有鼠标或触控板的设备上显示，和窗口宽度无关（和 IDE 并排开着时窗口很窄）。搜索框有内容时，提示换成清空按钮，不用浏览器自带的蓝色清除图标。

## Do's and Don'ts

### Do:
- **Do** 只通过语义变量取色（`bg`、`surface`、`line`、`fg-2`、`run`…），新颜色同时定义深浅两套值。
- **Do** 用反色墨 (`inv` / `inv-fg`) 做页面上唯一的主按钮。
- **Do** 让每个任务状态同时有形状和颜色：虚线圈、旋转弧、对勾圈、叉圈、斜杠圈。
- **Do** 所有数字等宽；会刷新的数值给固定列宽右对齐。
- **Do** 用 `Meter` 时按状态传填充色（`bg-run` / `bg-warn` / `bg-fg-3`）；不传时默认 `bg-fg-3`，漏传不会变成透明轨道。
- **Do** 状态变化时让该行按新状态的颜色闪一次（1.2s）；运行图标匀速 1.6s 一圈；细条数值变化用 500ms 的 `transform: scaleX` 过渡（不动 width，免得十几根细条每次轮询都触发重新布局）；其他交互只有 150ms 的颜色过渡。尊重 `prefers-reduced-motion`：关掉旋转、过渡和平滑滚动，只保留整行闪一下（只是底色淡出，没有位移，而且是这一行状态变了的唯一提示）。
- **Do** 日志、代码、命令、路径、commit 用系统等宽栈；日志和代码放进深色终端面板，两种主题都一样。
- **Do** 在手机上保留同样多的信息：改排版、改短格式，不删字段。
- **Do** 主题默认跟随系统，允许用 `<html data-theme>` 手动覆盖，并在首屏前由内联脚本提前应用以免闪烁。

### Don't:
- **Don't** 让信息密度比现在低：不加大行高、不把列表换成大卡片、不把字段藏进展开层。
- **Don't** 用朱砂色或任何橙色做按钮、链接、强调或背景；朱砂只属于火焰标志。
- **Don't** 用没有状态含义的颜色装饰分区、图标或标题。
- **Don't** 引入网络字体、打包字体或任何外部 CDN 资源。
- **Don't** 使用大于 8px 的圆角或粗圆角大卡片加橙色按钮的模板面板样式。
- **Don't** 给静止的面板加阴影；阴影只属于浮层。
- **Don't** 让日志或代码面板跟随浅色主题变白。
