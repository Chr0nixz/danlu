## Platform

web

丹炉桌面客户端是 Tauri 应用，界面跑在系统的 WebView 里。macOS 和 Windows 都支持，macOS 优先。设计和平台无关：两边看起来一样，不跟随任何一个系统的原生设计语言；只有平台惯例保留各自的做法：macOS 上是菜单栏图标、左上角的红黄绿圆点和 `⌘` 快捷键，Windows 上是托盘图标、右上角的窗口按钮和 `Ctrl` 快捷键。

## Users

只有一个用户：做深度学习训练的研究者，自己维护 2–3 台带公网 IP 的 GPU 服务器。客户端只装在用户自己的一台电脑上，Mac 或 Windows 电脑都可以。

客户端常驻菜单栏（Windows 上是托盘），和 IDE、终端并排：写代码时随时瞄一眼所有服务器的卡和任务；任务失败或服务器出问题时，被通知叫回来；需要时在这里跨服务器提交、重跑、复制任务，以及部署和维护各台服务器上的 danlu。要在某一台上深入看（快照 diff、任务对比、终端、预约、设置），就跳到那台的面板。

## Product Purpose

多台服务器的汇总层和运维工具，只做每台自带的 Web 面板做不到的三件事：一屏看清所有服务器的空卡和任务、常驻提醒失败和异常、通过 SSH 维护各台的 danlu。只涉及一台服务器的深入操作都在那台的面板里做，面板是单台服务器上的主力界面（电脑和手机都用），客户端不重做它的功能，只提供"在面板中打开"。

打开主窗口，第一眼要知道：

1. 有没有还没看过的失败；
2. 哪些任务在跑、跑到哪了；
3. 哪台服务器有空卡，能不能马上提交。

## Positioning

- **汇总在客户端完成**：同时请求每台服务器、在本地合并。服务器保持单机版，互相不认识，不需要主控节点。
- **以 SSH 为根**：能 SSH 登录就证明了身份。添加服务器不用输面板密码，也不用复制粘贴；部署、升级、服务管理都是通过系统自带的 ssh 执行一条 danlu 子命令。
- **不追平面板**：跨服务器的事归客户端，单台上的深入功能归面板。面板以后新加的单台功能，客户端最多加一个跳转入口，所以客户端只依赖接口里很小、很稳定的一部分。
- **结果能追溯到代码**：继承丹炉的核心，任何任务离它跑的 commit 和未提交改动只有一步。

## Operating Context

- 写代码、同步代码的流程不变：用户自己 rsync/scp 到各台服务器，客户端不碰本地代码。
- 各台服务器上的路径和 conda 环境名不一样，所以提交时必须先选服务器。项目名就是工作目录的最后一级；"项目 × 服务器 → 目录、环境"的对应关系记在客户端本地。
- 训练日志里有 tqdm 进度条和 ANSI 颜色，用户习惯在终端里读它们。
- 服务器可能和别人共用。外部进程占卡平常只在空卡条上标出来，只有挡住或可能挤掉自己的任务时才通知。
- 通知只报两类事：任务失败、服务器异常（连不上、外部进程影响到自己的任务、磁盘快满、`nvidia-smi` 报错）。同一件事只报一次。

## Capabilities and Constraints

- **已有（C1、C2，在 Windows 上做和验证，还没在 macOS 上运行过）**：
  - 服务器接入：通过 SSH 添加已经装好 danlu 的服务器，读取地址和 CA 证书，领取设备令牌。HTTPS 只信任各台服务器自己的 CA。
  - 主窗口：总览（空卡条 + 所有服务器的任务列表）、历史页、右侧分栏的任务详情。详情里有实时日志、日志搜索和下载、代码快照；这些保留，但不再往深里加。
  - 任务操作：提交、取消、重跑、复制任务（含复制到另一台）、命令历史。
  - 托盘：三种状态的图标，迷你总览，全局快捷键。
  - 通知：任务失败、连不上、`nvidia-smi` 报错、外部进程影响到自己的任务。
  - 运维：批量升级（先升一台）、服务管理。
  - 其他：键盘快捷键；设置页（通知、开机自启、快捷键、各台服务器上的设备令牌）。
- **计划（C3，暂停中）**：先做 macOS 版（菜单栏、系统标题栏圆点、`.dmg`），再回 Windows 复验；部署新服务器、机器体检和"磁盘快满"通知、`⌘K` 命令面板、"在面板中打开"（一次性登录票据免登录）、GitHub Actions 发布和自动更新（两种安装包都自带服务器程序，客户端和服务器统一版本号）。现阶段先迭代后端和 Web 面板，客户端不加新功能（`docs/ROADMAP.md`）。完整规划见 `docs/CLIENT.md`。
- **不做**：追平面板上只涉及一台服务器的功能（快照 diff、任务对比、网页终端、GPU 预约、严格限卡、保留策略和其他设置、审计日志）、上传或取回本地代码、自动选服务器、服务器之间组网、指标曲线（看 W&B / SwanLab）、Linux 桌面。手机推送由服务器通过 ntfy 发，客户端不管。
- **技术**：Tauri 2；界面是 React + TypeScript + Tailwind + TanStack Query，和面板共享 `packages/core`（接口、格式化、日志处理），但界面代码和样式各自独立。所有到服务器的请求都经过 Rust 层，界面从不直接访问服务器。凭据库（macOS 钥匙串、Windows 凭据管理器）、菜单栏和托盘、`⌘` 和 `Ctrl`、窗口按钮、安装包和签名这些平台相关的东西都放在小接缝后面。
- 界面语言：简体中文与英文，默认跟随系统，可在设置里手动切换（架构见 docs/I18N.md）。

## Brand Commitments

- 名字：丹炉（Danlu）。标志是朱砂色方块里的火焰，和面板相同。
- 文案口吻：关键信息一律直白（运行中、排队、失败、连不上），炼丹的说法只在空状态和标题里适度点缀。
- 视觉上和面板互不相干。用户定下的方向是：和平台无关的现代开发者工具，做工参照 Linear、Raycast，但更克制；颜色只表示状态，朱砂色只给火焰标志；窗口用纯色，不用云母、亚克力或半透明材质。具体取值以 `desktop/DESIGN.md` 为准。它是 C2 做完后从实际代码生成的；`docs/CLIENT.md` 第 5.4 节是最初的方向说明。

## Product Principles

1. **信息密度不能降**：要多滚动或多点一次才能看到同样的信息，就是改坏了。
2. **状态一眼可辨**：失败、运行、排队、外部占卡、服务器离线，不读文字也能分清。
3. **只在该打扰时打扰**：通知只报失败和异常，同一件事只报一次；平常安静地待在托盘里。
4. **结果能追溯到代码**：任何展示任务的地方，离 commit 和未提交改动只有一步。
5. **键盘优先，危险操作要确认**：常用操作都有快捷键；取消任务这类不能撤回的操作没有快捷键，必须点按钮并确认。

## Accessibility & Inclusion

系统开启"减少动态效果"时，关闭所有动效。
