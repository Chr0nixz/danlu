# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

丹炉桌面客户端是 Tauri 应用，界面跑在系统的 WebView 里。设计和平台无关：先做 Windows，以后支持 macOS，两边看起来一样，不跟随任何一个系统的原生设计语言。

## Users

只有一个用户：做深度学习训练的研究者，自己维护 2–3 台带公网 IP 的 GPU 服务器。客户端只装在他自己的一台电脑上（先是 Windows，以后是 macOS）。

客户端常驻托盘，和 IDE、终端并排：写代码时随时瞄一眼所有服务器的卡和任务；任务失败或服务器出问题时，被通知叫回来；需要时在这里提交、重跑、复制任务，以及部署和维护各台服务器上的 danlu。

## Product Purpose

在一台电脑上统一管理所有服务器：一屏看清所有服务器的空卡和任务，操作任务，维护 danlu 本身。每台服务器自带的 Web 面板继续保留，给手机和客户端出问题时兜底；电脑上以客户端为主。

打开主窗口，第一眼要知道：

1. 有没有还没看过的失败；
2. 哪些任务在跑、跑到哪了；
3. 哪台服务器有空卡，能不能马上提交。

## Positioning

- **汇总在客户端完成**：同时请求每台服务器、在本地合并。服务器保持单机版，互相不认识，不需要主控节点。
- **以 SSH 为根**：能 SSH 登录就证明了身份。添加服务器不用输面板密码，也不用复制粘贴；部署、升级、服务管理都是通过系统自带的 ssh 执行一条 danlu 子命令。
- **结果能追溯到代码**：继承丹炉的核心，任何任务离它跑的 commit 和未提交改动只有一步。

## Operating Context

- 写代码、同步代码的流程不变：用户自己 rsync/scp 到各台服务器，客户端不碰本地代码。
- 各台服务器上的路径和 conda 环境名不一样，所以提交时必须先选服务器。项目名就是工作目录的最后一级；"项目 × 服务器 → 目录、环境"的对应关系记在客户端本地。
- 训练日志里有 tqdm 进度条和 ANSI 颜色，用户习惯在终端里读它们。
- 服务器可能和别人共用。外部进程占卡平常只在空卡条上标出来，只有挡住或可能挤掉自己的任务时才通知。
- 通知只报两类事：任务失败、服务器异常（连不上、外部进程影响到自己的任务、磁盘快满、`nvidia-smi` 报错）。同一件事只报一次。

## Capabilities and Constraints

- **已有（C1）**：通过 SSH 添加已经装好 danlu 的服务器（读取地址和 CA 证书，领取设备令牌）；只信任各台服务器自己 CA 的 HTTPS；总览（空卡条 + 所有服务器的任务列表）；右侧分栏的任务详情和实时日志；已读的失败记在本地。
- **计划**：C2 托盘和迷你总览、全局快捷键、通知、提交/取消/重跑/复制任务（含复制到另一台）、命令历史、代码快照、历史页、批量升级（先升一台）、服务管理、键盘快捷键；C3 部署新服务器、机器体检、`Ctrl+K` 命令面板、自动更新。完整规划见 `docs/CLIENT.md`。
- **不做**：上传或取回本地代码、自动选服务器、跨任务对比、服务器之间组网、指标曲线（看 W&B / SwanLab）。手机推送以后再说。
- **技术**：Tauri 2；界面是 React + TypeScript + Tailwind + TanStack Query，和面板共享 `packages/core`（接口、格式化、日志处理），但界面代码和样式各自独立。所有到服务器的请求都经过 Rust 层，界面从不直接访问服务器。凭据库、托盘和菜单栏、`Ctrl` 和 `⌘`、窗口按钮这些平台相关的东西都放在小接缝后面。
- 界面语言：简体中文。

## Brand Commitments

- 名字：丹炉（Danlu）。标志是朱砂色方块里的火焰，和面板相同。
- 文案口吻：关键信息一律直白（运行中、排队、失败、连不上），炼丹的说法只在空状态和标题里适度点缀。
- 视觉上和面板互不相干。用户定下的方向是：和平台无关的现代开发者工具，做工参照 Linear、Raycast，但更克制；颜色只表示状态，朱砂色只给火焰标志；窗口用纯色，不用云母、亚克力或半透明材质。具体取值在 `docs/CLIENT.md` 第 5.4 节，C2 生成 `desktop/DESIGN.md` 后以它为准。

## Evidence on Hand

没有用户、评价或使用数据可以引用。开发和演示用的是 WSL 里的假 GPU（`DANLU_FAKE_GPUS`）和演示任务，只能当演示，不能当真实案例展示。

## Product Principles

1. **信息密度不能降**：要多滚动或多点一次才能看到同样的信息，就是改坏了。
2. **状态一眼可辨**：失败、运行、排队、外部占卡、服务器离线，不读文字也能分清。
3. **只在该打扰时打扰**：通知只报失败和异常，同一件事只报一次；平常安静地待在托盘里。
4. **结果能追溯到代码**：任何展示任务的地方，离 commit 和未提交改动只有一步。
5. **键盘优先，危险操作要确认**：常用操作都有快捷键；取消任务这类不能撤回的操作没有快捷键，必须点按钮并确认。

## Accessibility & Inclusion

系统开启"减少动态效果"时，关闭所有动效。
