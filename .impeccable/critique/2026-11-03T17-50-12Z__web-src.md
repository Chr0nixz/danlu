## 设计特异性结论

**LLM 评估。**面板忠实执行了用户选定的方向，也就是同类产品的标准控制台。结构是摘要一行、GPU 卡片、Linear 式分组列表、带标签页的详情页，形式上可以是 Vercel 或 GitHub Actions，这正是简报要求的。产品个性体现在内容上，不在形式上：

- tqdm 进度压成短格式：`epoch 23/500: 2% · 2/100 [loss=0.1086]`
- 服务端提取报错行并分类：`CUDA 显存不足 · RuntimeError: CUDA out of memory…`
- 排队原因点名阻塞者：`第 1 位 · 等待 2 张空闲卡（当前 0 张可用）；GPU 3 有外部进程（PID 900003）`
- 每行的 commit 都带"有未提交改动"圆点，并链接到快照
- 重跑页提示 HEAD 和快照不同
- 对比页列出环境变量差异

电脑端做工达到了对标产品的水平，手机端明显不到，原因是任务行在窄屏上排不下。只属于这个产品、却还没做的有三处：

- 代码追溯要到提交之后才看得见，新建表单不告诉你会记录哪一版代码。
- GPU 特有的状态没有单独表示。占着卡但利用率为 0%，看上去和正常运行一样，都是平静的蓝色。
- 电脑首屏最显眼的位置给了 CPU/内存曲线，这是任何服务器面板都有的东西。

**确定性扫描。**`impeccable detect --json web/src` 退出码 0，共 21 条提示级发现，没有主要发现；`--no-config` 时 0 条，说明通用反模式规则一条都没触发。

- `design-system-color` ×20，全部在 `index.css:217-239`，是 ansi_up 的 `.ansi-*` 颜色。**误报**：这些值写在 `web/.impeccable/design.json` 的 `ansiPalette` 里，只用在深色终端里，而 DESIGN.md 允许终端里直接写色值。检测器没有读 sidecar 里的这个键。
- `design-system-font-size` ×1，`Terminal.tsx:119` 用了 `text-[10px]`。**真问题（小）**：比最小字级 Micro 11px 还小。

浏览器内注入检测器后的结果：

- 总览、任务页、设置页共报 `nested-cards` 3 处：分组标题栏、列头、ntfy 面板的底栏。**误报**，这些都是 DESIGN.md 规定的条带，不是嵌套卡片。
- 详情页报 `pulsing-status-dot` 1 处，是日志"实时"点。**误报**，DESIGN.md 明确要求这个点。
- 电脑端失败原因的 `text-overflow`：截断是有意的，也有 title。但在 1024px 宽时只露出 451px 里的 226px。
- 手机总览报 `text-overflow` ×7，全是任务名，溢出 33–135px，都没有 title。**真问题**，和设计评审的实测结论相互印证。

两边一致的地方：手机任务名被截。检测器补上的、设计评审没注意到的有三处：终端标签页的 10px 字；GPU 面板里占卡者名字被截且没有 title；1024px 宽时失败原因和排队原因有一半以上被截掉。检测器看不到、只有设计评审能发现的是：信息架构（主机资源的位置）、操作的主次、流程断头、焦点行为。

**可视叠层。**注入成功，叠层画在浏览器窗格里检测器的那个标签页上（总览页，1024px 宽，8 处标记）。演示服务器已经停了，页面不会再刷新，但叠层会一直留着，直到页面重新加载。

## 总体印象

系统层面很扎实：颜色纪律、状态的图标和措辞、代码追溯这条线都站得住，两套主题都没出问题。问题集中在两处排版：手机上的任务行，以及任务详情页的操作区。最大的机会是把"失败 → 改参数重跑"做成一条走得通的路，并让首屏只回答 PRODUCT.md 列出的那三个问题。

## 做得好的

1. **状态的图标和措辞经得起看。**五种状态同时用形状和颜色区分（虚线圈、旋转弧、对勾、叉、斜杠），色盲也能读。说明文字跟着状态走，排队的任务写位次，还点名挡路的 PID。数据过期有提示，状态变化时整行闪一次。两套主题实测都成立。
2. **每个界面都能追到代码。**每一行的 commit 都带"有未提交改动"圆点，点一下就到快照，快照浏览器有行号。重跑页直说"重跑会使用工作目录现在的代码，不是原任务快照里的那份"（`NewJob.tsx:358-395`）。对比页把唯一不同的环境变量 `FAIL` 单独列出来。"跑的是哪版代码"这个问题有答案。
3. **失败和取消的文案先讲后果。**报错行原样出现在列表、详情页失败框和重跑页标题下方，并带分类。取消确认框写的是"已经运行 4分25秒。确定后进程会被结束，不能恢复；日志和代码快照会保留。"。焦点默认落在"继续运行"上，手机上确认框贴着屏幕底部，拇指够得到。

## 认知负荷与情绪路径

按清单有 5 项不通过（高负荷）：单一焦点、分块、视觉层级、最少选择、工作记忆。其中"分块"和"最少选择"有一部分是密度底线换来的，不该机械地砍。真正的过载集中在任务详情页的操作栏（6 个同样分量的按钮）。

超过 4 个选项的决策点有三个：

- 详情页操作 6 个
- 任务筛选 8 个控件
- 总览每行 5 个可点目标：整行、commit、标星、复制、取消

情绪路径的高点有三个：标签页标题里的计数、列表里直接出现的红色报错行、取消确认框。低点出现在夜里用手机看的时候：`#8 conv…` 和 `#9 mae…` 分不清是哪组消融；最新的两行日志压在导航下面。失败这条路的结尾也是低点：失败框最后一个动作是"看日志末尾"，而不是"改了再跑"。

## 优先问题

**[P1] 手机任务行把任务名压到 3–7 个字符**

- **是什么：**375px 宽时，任务名只有 44–70px，截图里是 `vit-l16 …`、`conv…`、`mae…`。设计评审实测了宽度，检测器也报了 7 处溢出（33–135px，都没有 title），两边结论一致。
- **原因：**
  - 名字前有一个 44px 的手机标星占位（`JobRow.tsx:115-117`）。
  - 右侧是复制和取消两个 44px 点击区（`JobRow.tsx:177-203`），总览的三个分组都打开了 `showCopy`（`Home.tsx:127,131,145`）。
  - 时间也挤在第一行。
- **为什么重要：**名字是任务的主标识，消融实验靠后缀区分（`lr=1e-4`），被截掉的恰恰是后缀。这违反了原则 4（手机和电脑同等重要）和信息密度底线。
- **怎么改：**
  1. 把标星移出手机上的名字行，详情页本来就有。
  2. 复制和取消在手机上合成一个 44px 的 `⋯`，或者只在运行和排队的行上保留取消。
  3. 时间移到第二行。
  4. 名字允许折成两行。
  - 注意：手机上常显复制图标是 DESIGN.md 写明的，要改就同步改文档。
- **建议命令：**`/impeccable adapt web/src`

**[P1] 电脑首页：主机资源把失败的任务挤出了首屏**

- **是什么：**1440×900 下，主机资源从 y≈265 开始，占约 310px；"运行中"从 593 开始；失败的 #2 在 y≈1080，在首屏之外。可摘要里明明写着"1 失败"。
- **为什么重要：**PRODUCT.md 列的首眼三件事（跑完没有、有没有挂；进度和日志；卡空不空）里没有 CPU 曲线。一条 2% 的 60 秒平线支撑不了任何决定，却拿着全页最大的数字（`HostMetrics.tsx:110`）。
- **怎么改：**任选其一：
  - 电脑上也把主机资源放到任务列表后面。手机已经是这个顺序（`Home.tsx:118` 对比 `:148`）。
  - 压成一条 36px 的单行，比如 `CPU 2% · 内存 2.8/31.2 GiB · 磁盘 880 GiB 可用`，磁盘只在告警时变色。
  - 注意：两种改法都要改 DESIGN.md 的 Layout 一节，那里规定了首页的顺序。
- **建议命令：**`/impeccable layout web/src`

**[P1] 任务详情：6 个同样分量的按钮；手机上最新日志压在导航下**

- **是什么：**
  - 操作栏有 6 个按钮：标星、终端、W&B、重跑、和…对比、取消，全是次按钮（`JobDetail.tsx:103-131`），没有主操作。
  - 手机上操作栏折成两行，MetaStrip 占三行，日志框从 516px 处开始。`.log-fit` 因此降到 280px 的下限（`index.css:200`），最新约两行日志压在底部导航下面。
  - 代码标签页里，代码大约从 860px 处才开始。
  - 危险按钮只写"取消"（`JobDetail.tsx:128`）。
- **为什么重要：**在手机上打开一个运行中的任务，就是为了看最新的日志。"取消"两个字在中文界面里容易读成"关掉这个对话"。
- **怎么改：**
  1. 每种状态只设一个主操作：运行中是"取消任务"，失败是"改参数重跑"，成功是"重跑"。其余操作收进 `⋯`。
  2. 手机上把 MetaStrip 压到两行。
  3. 页面挂载后，让日志框底部对齐到导航上方。
  4. 按钮文字改成"取消任务"。
- **建议命令：**`/impeccable adapt web/src`（配合 distill）

**[P2] 失败以后"再跑一次"这条路是断的**

- **是什么：**
  - 失败框里只有"看日志末尾"或"跳到报错"（`JobDetail.tsx:195-221`）。
  - 首页的行上只有"复制"，详情页只有"重跑"，两者的结果不一样。复制保留原名，不记录来源；重跑会加后缀、记录来源，还能选用快照里的代码。
  - 重跑默认"现在的工作目录"，而它正上方就是"和快照不同"的警告（`NewJob.tsx:177-182`）。
- **为什么重要：**失败是压力最大的时刻，按峰终定律，结尾是死胡同的体验会被记住。默认值也和产品存在的理由（代码可追溯）相反。
- **怎么改：**
  1. 在失败框里放"改参数重跑"，作为失败任务页面上唯一的主操作。
  2. 按失败分类给一句提示。显存不足："减小 batch size 或多申请一张卡"；服务器重启："原样重跑"。
  3. 代码来源改成两格的分段控件，每格写出 commit 和有没有未提交改动。
  4. 考虑把复制和重跑统一成一个动词。
- **建议命令：**`/impeccable clarify web/src`

**[P2] 键盘、读屏和触控的硬化**

- 空提交时，焦点移到工作目录（`NewJob.tsx:117`），而它的 `onFocus`（`:453`）会打开目录下拉，盖住"请填写工作目录"和命令字段的错误；读屏读到的也是展开的组合框，而不是错误。改成只在输入或按 ↓ 时打开下拉。
- 总览页没有 h1，GPU 区没有标题。任务状态变化没有读屏播报，而 DESIGN.md 里整行闪烁就是唯一的提示。
- 代码行号是 `#5a5a5a` 配 `#0b0b0b` 底，对比度约 2.85:1（`CodeBrowser.tsx:218`）。行号要和 traceback 对得上，属于信息，不是装饰。
- 手机上的触控区偏小：详情页操作按钮 32px，确认框按钮 36px，文件树的行 28px（目录按钮也缺 `aria-expanded`），最近工作目录的小标签 24px。
- 登录页用了浏览器自带的必填气泡（`Login.tsx:51,54`），和 DESIGN.md 冲突。
- **建议命令：**`/impeccable harden web/src`
